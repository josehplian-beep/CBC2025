# Remove Lovable branding from source code

## Goal
Scrub user-visible and source-code references to "Lovable" so the codebase and published site do not reveal the platform used to build it.

## Current state (verified)
- `src/index.css:146` contains `#lovable-badge { display: none !important; }`.
- `src/integrations/supabase/previewAuthStorage.ts` is auto-generated and contains multiple "Lovable" references: comments, preview-zone domain names (`lovableproject.com`, `lovable.app`, etc.), editor-origin regexes (`lovable.dev`), and postMessage protocol strings (`lovable-preview-auth:*`).
- `bun.lock` contains many `lovable-core-prod` npm registry URLs and a `lovable-tagger` package reference, but lockfiles are generated artifacts.
- The "Edit with Lovable" publish badge is already hidden via project publish settings.

## Proposed changes
1. **Remove the badge CSS rule**
   - Delete `#lovable-badge { display: none !important; }` from `src/index.css`.
   - Rationale: the badge is already hidden at the publish-settings level; the CSS selector is the only remaining user-visible "lovable" string in styling.

2. **Sanitize comments and naming in `previewAuthStorage.ts` without breaking preview auth**
   - Rewrite comments to describe the functionality generically (e.g., "preview surface" / "editor ancestor" instead of "Lovable preview surface" / "Lovable origin").
   - Rename local variables like `EDITOR`, `RESULT`, `request` only where it does not change runtime behavior.
   - **Keep unchanged** the actual domain arrays and postMessage type strings (`lovableproject.com`, `lovable.app`, `lovable.dev`, `lovable-preview-auth:*`). These are the wire protocol with the preview/editor environment; altering them would break auth brokering inside the Lovable editor/preview.

3. **Leave generated files alone**
   - Do not edit `bun.lock` or `node_modules`. They are regenerated by the package manager and build pipeline; manual changes would be overwritten and could corrupt dependency resolution.

4. **Verification**
   - Run `bun run build` to confirm the app still compiles.
   - Grep for remaining "lovable" strings in `src/` and `index.html`; expect only the functional preview-auth protocol/domains to remain.

## Out of scope
- Removing the functional preview-auth domains and message types from `previewAuthStorage.ts`, because doing so would break the editor's shared-login feature.
- Editing `bun.lock` or `package.json` registry URLs, because they are generated/managed by the package tooling.
